01 / 任務與學習目的

為一家自選或虛構公司建立能說清楚品牌、展示產品、建立信任、引導詢問的現代公司網站。

本次以HTML＋CSS為核心，開放ChatGPT、Gemini與其他主流AI模型。每個設計決策都要說明目的、做法、取捨與驗證；網站成品與設計說明一起評分。

內容資訊完整、資料一致
設計三套風格、色盤與排版
互動操作目的與回饋清楚
品質手機、鍵盤、來源與測試
最低成果：八個主要頁面＋至少兩個產品詳細頁＋design.html＋兩個替代風格首頁，共至少13個HTML檔；完整主站採一套風格，另兩套只需首頁。至少五項產品、三位人員、六項活動、三則最新消息、五題FAQ、四項有目的的互動；再完成兩個深化模組。

建議2–3人一組，分組依教師公告。這份加強版是作業規格，不是要求你一次建立具有後台、交易與客服系統的正式服務。

03 / 現代公司網站應考慮的內容與品質

公司的業務不同，網站內容也不同。本表是需求思考框架；「必修」是這次課堂練習要求，「選做」依品牌與技術能力選擇。

面向商業／資訊目的本次要求
品牌與價值主張說清楚做什麼、為誰解決什麼問題必修：首頁定位、特色與一致品牌語氣
產品／服務資訊讓訪客了解規格、價格與適用限制必修：五項產品、兩個詳細頁；不只放圖片
行動入口CTA讓閱讀後的下一步明確必修：首頁兩個有效入口；每項產品有詢問或詳細連結
信任與證據讓宣稱可檢查必修：案例／成果有來源或標虛構；不編造真人推薦、認證或客戶Logo
聯絡與服務降低詢問與使用門檻必修：聯絡入口、服務時間、五題FAQ與售後資訊
最新消息與更新日期區分近期資訊與舊內容必修：三則消息、日期、分類、摘要、可閱讀詳情
隱私與資料處理說明說清欄位用途與展示版限制必修：簡短資料說明；正式網站按實際服務另行設計
手機與不同螢幕保留內容與操作品質必修：360／768／1280px；全頁不水平溢出
鍵盤與文字可讀性讓不同操作方式能使用必修：焦點、alt、label、語意、文字對比
搜尋可理解的內容讓頁名與文字能描述內容必修：獨特title、description、標題、連結文字；SEO不保證排名
圖片與效能避免大圖拖慢或擠破版面必修：圖片尺寸、壓縮、width／height與檔案大小紀錄
內容維護與元件系統讓新增產品不必重寫全站必修：外部CSS、共用元件、變數、來源與更新規則
搜尋、篩選、雙語依產品量與市場需要深化選做：有真實功能與狀態才呈現
購物車、登入、支付、聊天、追蹤只在相應業務需要時整合不列期中必修；畫面原型不能宣稱可真實交易

首頁不是資料總表

先理解品牌定位、主標題、簡介
再探索產品、服務、案例與消息
建立信任團隊、來源、服務資訊
採取行動查看詳細、詢問、聯絡

不必先區分不同身分。用內容主題組織導覽，讓訪客自然探索。CTA是下一步操作，不是每一個段落都加一個醒目按鈕。

04 / 八個主要頁面與兩個詳細頁

全部必修 八個主要頁面指首頁、簡介、產品總覽、團隊、行事曆、財務、消息、回饋。產品詳細頁、design.html與替代首頁另計。

檔名頁面最低內容驗收
index.html首頁公司名稱／識別、品牌標語、清楚價值主張、三項特色、產品摘要、近期消息、至少兩個有效CTA。第一眼能知道公司做什麼；可進入產品或詢問。
about.html公司簡介至少300字，含創立背景、使命、核心理念、主要市場與至少三項里程碑；引用主張標來源。定位與產品、團隊、服務承諾一致。
products.html產品總覽至少五種不同產品；每項含名稱、圖片／alt、至少80字說明、價格或區間、至少三項規格、適用情境與有效入口。不是五個名稱不同但內容相同的卡片；產品能比較。
product-01.html等至少兩個產品詳細頁每頁至少200字；產品價值、兩張相關圖／示意圖、規格表至少五列、使用情境、限制與售後摘要、兩題FAQ、詢問入口與返回總覽。總覽與詳頁名稱、價格、圖片和規格一致；兩頁獨立。
team.html公司人員至少三位；姓名、職稱、圖片／插圖／文字識別、專長、至少60字職責說明。可用虛構人物。說明角色如何支援公司產品與服務；不暴露同學私人資料。
calendar.html行事曆完整一個月份、至少六項活動、至少兩種類別；月曆＋文字清單；每項有日期、時間、地點、目的與參與方式。日期與星期正確；重要資訊不只靠顏色。
finance.html財務報表至少四季或六個月簡化營業損益；營收、營業成本、營業費用、營業利益、合計、年度、單位；一張CSS圖表＋三個解讀指標。營業利益與合計可驗算；圖表尺度一致；虛構資料清楚標記。
news.html最新消息／品牌動態至少三則；日期、類別、標題、至少80字摘要與可閱讀詳情。可在同頁使用錨點／details。與品牌有關；示例與真實公告分清；舊消息可辨識。
feedback.html聯絡／回饋／服務資訊可見聯絡方式與服務時間；稱呼、Email、類別、意見內容、展示確認；label、required、格式與長度限制；至少五題FAQ及資料處理說明。驗證可重現；錯誤／預覽說明清楚；不假裝已保存或寄送。
design.html設計比較與決策A／B／C入口、理念、色碼角色、字級／間距／元件規則、布局與互動規格、六張截圖、至少300字選擇與取捨、測試修正。內容、配色、排版和互動選擇有具體理由。

全站共同要求

  • HTML5、UTF-8、lang="zh-Hant"、viewport、各頁獨特title與description；每頁一個主要h1。
  • 使用header、nav、main、section／article、footer。內頁有有效返回入口；目前導覽以aria-current標示。
  • 主要頁面共用主風格與元件。兩個替代首頁導覽可回主站，不需複製整套內頁。
  • 聯絡／服務入口與頁尾可在所有頁面找到。禁止空連結、偽搜尋框、未完成按鈕與「Lorem ipsum」。
  • FAQ可分布產品或服務頁，但回饋／服務頁至少五題。實體產品可說配送、保固與退換；服務型產品可說交期、支援與修改流程。

05 / 三套首頁：風格、配色、排版都要有差異

設計理念與方案比較共45分。三套首頁保持同一品牌、文案、產品與核心內容。用不同CSS呈現：視覺風格、色彩角色、字體／字重、間距、布局、框線／圓角／陰影。

方案範例風格與配色排版方向選擇理由應討論
A 明亮極簡#F5F7FA底／#172B4D正文／#005FCC主色／#007A65輔色簡潔主視覺、規則卡片網格、充分留白適合哪些內容？如何保持產品與正文清楚？
B 深色科技#0B1220底／#F1F5F9正文／#67E8F9主色／#C4B5FD輔色左右分區、Bento大小卡片、分層區塊研究／科技氣氛怎樣呈現？亮色按鈕為何用深色字？
C 鮮明幾何#FFF9E8底／#171717正文／#FFE066主色／#B9F5D8輔色大標題、置中或不對稱區塊、粗框與硬陰影品牌個性如何建立？大量粗框是否影響長文字閱讀？
可自選暖色編輯#FAF7F0底／#2D241F正文／#285B48主色／#A43B25輔色襯線標題、雜誌圖文、故事式節奏圖片與文字怎樣引導主次？手機如何重排？

以上為教學配色與設計方向，不是流行度排名，也不是指定模板。可自選三套，但不能只換背景或按鈕顏色。

每個方案寫出四項

目的與做法

想讓訪客先理解什麼？資訊順序、版型、色彩與字級怎麼支援目的？

取捨與驗證

這方案犧牲了什麼？用手機、鍵盤、查找任務或可讀性比較來驗證。

先固定內容做灰階布局，再上色。可先一次只改配色或布局，最後整合為三個完整方案。每套各交360px與1280px截圖，共六張；主站另驗證768px。

06 / 公司網站的八個設計理念

理念如何體現在本作品
資訊組織內容分類、有效導覽、返回路徑；同一產品資料跨頁一致。
視覺層級主標題、特色、產品、信任證據與CTA有明確先後。
配色角色底色、正文、連結、強調、狀態各有用途；不只靠顏色傳訊息。
文字與留白長文分段、合理行高、固定字級與間距；保持中文可讀。
版型關係並列項目用網格，過程用步驟，重點故事用主次布局。
互動回饋明確觸發、狀態、結果與返回；必要資訊不藏在hover。
一致與維護共用卡片、按鈕、導覽、表格；用變數與元件規則降低重複。
RWD與包容性欄位重排、表格局部捲動、焦點、alt、label與減少動態。

設計理由示例

目的：讓訪客在產品總覽比較五種產品。

做法：以同一結構卡片呈現名稱、價格、用途、三項規格與詳細入口；正文深色，主要行動用品牌色。

取捨：卡片適合概覽，但長文會使卡片不齊；摘要精簡，詳細資訊放獨立頁。

驗證：請同學找出適合某情境的產品、價格及售後資訊，並檢查手機單欄。這是紀錄格式示例，實際結果需自己測試。

07 / 至少四項有目的的互動

必修 至少四種不同互動，其中至少三種用HTML＋CSS／原生HTML完成；第四種也可以用HTML＋CSS。不要把四個相同hover效果算成四種互動。

互動選項目的技術與驗收
FAQ展開先看到問題，再閱讀細節details／summary；開閉、鍵盤、手機可操作
產品比較分類切換一小組資訊原生radio＋CSS或不同分類頁；目前選項清楚
圖庫探索查看產品不同角度／情境水平捲動＋scroll snap；必備圖片與文字不隱藏
活動定位從月曆看到活動詳情錨點連結與有效id；可返回月曆
表單驗證避免遺漏或格式問題required、type=email、minlength；五個錯誤情境實測
卡片／按鈕回饋讓可點擊與目前焦點明確hover＋focus-visible，必要內容一直可見；只計一類
產品篩選／搜尋縮小產品集合選做JS；結果數、無結果、重設、鍵盤完整
即時風格或圖表切換比較方案或資料選做JS；目前設定與資料一致，不影響基本閱讀

每項互動在design.html寫：目的、觸發、初始／操作後狀態、回饋、關閉／返回、鍵盤與手機測試。輪播、影片與動態效果應能停止或依偏好減少；不需要自動播放。

原生FAQ最小範例

<details>
  <summary>如何取得保養或服務資訊？</summary>
  <p>此頁為虛構品牌教學示例；實際作業請說明服務流程。</p>
</details>
summary { cursor: pointer; font-weight: 700; }
summary:focus-visible { outline: 3px solid #005FCC; }

操作回饋與減少動態

.card-link:hover, .card-link:focus-visible {
  border-color: #005FCC;
  transform: translateY(-3px);
}
.card-link:focus-visible { outline: 3px solid #005FCC; }
@media (prefers-reduced-motion: reduce) {
  .card-link { transition: none; }
  .card-link:hover, .card-link:focus-visible { transform: none; }
}

08 / 深化必修：從六種模組選兩種

選兩項完成 可整合到既有頁面，不一定另外加頁。要有完整內容與驗證證據，不能只寫一句「提供優質服務」。基本頁面中的最低FAQ或一般產品列表不能直接當成兩個深化模組。

深化方向最低成果驗收
產品比較至少三項產品、六個比較欄位、各自適用情境；表格與總覽數據一致。比較三種產品後能解釋如何選擇。
服務／售後流程至少四個步驟、時間／限制、服務入口；實體／數位服務依題材調整。訪客知道詢問後怎麼進行，不虛構已接單。
案例／成果故事至少兩個案例：問題、做法、結果、證據／虛構標記；不是空泛好評。數字有來源或明確標示示例。
資源與文件下載至少兩份原創PDF／文字／HTML文件，標檔名、版本／日期、下載入口。每個檔案真的存在，內容與網站一致。
品牌／永續透明度材料／維修／限制說明；至少三項可查證或教學設定，不能捏造認證。區分理念、已做到與尚未做到的事項。
雙語或進階功能擇一：首頁與兩個關鍵區塊的雙語版本；或真實產品篩選／搜尋。雙語意義一致且可切換；篩選有無結果與重設。

完成更多模組不自動加分。先確保兩項深化與全部核心項目完善，再做進一步探索。

10 / 回饋表單：標籤、驗證與功能界線

稱呼、Email、類別、意見內容與展示確認是必修；可加滿意度、產品選擇等與目的相關的欄位。用label、fieldset／legend、提示與原生限制協助填寫，不以placeholder取代label。

<form action="feedback-preview.html" method="get">
  <p>靜態展示版：請使用虛構資料，沒有保存或寄送服務。</p>
  <label for="email">Email（必填）</label>
  <input id="email" name="email" type="email" required
         placeholder="student@example.com">
  <label for="message">意見內容（10–500字）</label>
  <textarea id="message" name="message" rows="6"
            required minlength="10" maxlength="500"></textarea>
  <button type="submit">預覽填寫流程</button>
</form>

GET會把有name的欄位值放在網址，HTTP環境也會帶在頁面請求中。因此只用虛構資料。預覽頁不宣稱已送達，也不將網址值渲染成HTML。

原作業的mailto方式如何保留

<!-- 可選寄信示範；依賴裝置已設定的郵件程式 -->
<form action="mailto:contact@example.com"
      method="post" enctype="text/plain">
  <label for="mail-message">示範內容</label>
  <textarea id="mail-message" name="message" required></textarea>
  <button type="submit">開啟郵件程式（示範）</button>
</form>

mailto可能開啟預設郵件程式，但各瀏覽器／裝置行為不同，仍需使用者確認寄出；示例地址不可當真實接收服務。基本評分以表單標籤、驗證、状態與限制說明為主，不以mailto是否彈出當唯一通過條件。

必測五種情境

  1. 全部必填空白，不能進入預覽。
  2. Email填abc，出現格式提示。
  3. 類別未選，不能進入預覽。
  4. 意見手動輸入少於10字，長度限制有效。
  5. 完整虛構資料可預覽；預覽頁不表示公司已收到。Tab順序與重設也要測試。

資料說明需寫出欄位用途、此示例是否保存、是否寄送、聯絡入口。正式上線的隱私與服務流程需依實際資料處理另行設計；本作業不蒐集真實客戶資料。

11 / 現代網站品質：RWD、可讀性、SEO與效能

RWD與無障礙基本檢查

  • 360／768／1280px：欄位重排、長標題、導覽、圖片、表格與表單都可讀。
  • 全頁不水平溢出；寬表格可在獨立容器捲動。至少測一次200%文字縮放。
  • Tab能走過全部連結與欄位，焦點清楚。必要資訊不藏在hover。
  • 圖片alt描述必要資訊，裝飾圖片可用空alt；表格有caption與scope；表單label對應id。
  • 正文與一般按鈕文字以對比至少4.5:1為本課目標；這不等於整站已達完整WCAG合規。
  • 動畫與平滑捲動考慮prefers-reduced-motion，不強迫自動播放。

SEO以內容清楚為起點

每頁獨特title與合理description，正文有真正的品牌／產品內容，h1／h2層級清楚，連結用「查看森光桌燈規格」等描述性文字。網站需要公開可存取與可索引才可能出現在搜尋結果；本機作業不要求實際被Google收錄，也不承諾排名。

<html lang="zh-Hant">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>森光桌燈｜森日生活設計</title>
  <meta name="description"
        content="認識森光桌燈的設計、規格、適用情境與保養方式。虛構教學產品。">
</head>

圖片與效能

使用與呈現尺寸相近的圖片，記錄檔名、尺寸、格式與大小；至少一張圖片展示壓縮前後比較。可用WebP、AVIF、JPEG或SVG，依內容選擇；照片不要只靠CSS把多MB大圖縮小。

<img src="assets/product-01.webp" alt="桌燈燈臂與底座的外觀"
     width="800" height="600" loading="lazy">
/* 首屏主要圖片通常不使用lazy；此例適合下方產品卡片 */
img { max-width: 100%; height: auto; }
.product-image { aspect-ratio: 4 / 3; object-fit: cover; }

width／height有助保留圖片空間；實際圖片與裁切應合理。核心驗收是資源清單、尺寸、相對路徑與壓縮紀錄；HTTP環境下的Lighthouse或Core Web Vitals報告可做深化觀察，實驗室分數不代表真實訪客的所有體驗。

常見的Cookie提示、聊天、分析追蹤或付款元件依業務與實際服務決定；本課不需要加入假的同意按鈕、追蹤腳本、聊天服務或交易流程。

13 / AI協作：問理由、分步生成、親自驗證

允許所有主流AI工具；不依付費模型或使用次數加分。可用AI發想、生成程式、改文案與除錯，但不能以AI聲稱「正確」代替自己的測試與理解。

我要做HTML＋CSS的公司網站期中專題。
公司：[名稱、產品、定位]。核心內容：[貼企劃]。
請先提出三個首頁方案，保留相同核心內容，
分別說明資訊層級、配色角色、字體、排版與互動目的。
每個方案列優點、代價、360px重排方式與測試項目。
不要先一次寫全站，也不要編造認證、客戶或數據。
等我選方案後，再分段生成HTML與共用CSS。
這是產品總覽與詳細頁：[貼相關程式]。
請檢查名稱、價格、規格與連結是否一致，
指出冗餘或缺漏，並給最小修改。
另外檢查：360px溢出、鍵盤焦點、圖片alt、
原生表單驗證、財務公式與月曆星期。
每項建議附可重現的測試步驟；不知道的事實請標待查。

ai-log.md至少三筆紀錄：工具／日期、原問題與提示、採用與修改、測試結果、自己的理解。未使用AI可交三筆自主學習與除錯紀錄。sources.md標出圖片、圖示、字體、數據、文案、模板或程式片段的來源與使用條件；自畫與AI生成也要註明。
